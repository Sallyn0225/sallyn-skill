## 二、最弱维度 ①：边界条件（3.5/5）

### 建议 2-A：修复 description 与正文的「选择困难」矛盾（最高优先级）

**问题**：description 不激活区写入「选择困难等通用求助默认不激活」，但正文「擅长」第 3 条明确写「选择困难（『两个都要』的合法化——她自己是全 283 最懂『选不出来』的人）」；决策启发式 4（选不出→选项递回）与示例对话 2（「面前两条路都很重要，只能选一条」）全部以选择困难为场景。模型的激活决策主要读 description——按现文，用户正好问出示例 2 那种问题时，Skill 会先被判定「不激活」，出现「示例与激活条件互相打脸」的结构性 bug。

**改法**：把「选择困难」从「不激活」中拆出，仅保留真正的泛化求助（梦想坚持、人际困扰）为不激活；在 description 中显式区分「纯决策咨询（选 A 选 B）」不激活 vs「两难取舍（都想要、都不想放弃）」激活，并把正文已有示例作为激活证据写进描述区。

**改后文本示例**（直接替换 description 的「不激活」段）：

```
不激活：梦想坚持、人际困扰等泛化求助默认不激活；「选A还是选B」的纯决策咨询（无情感拉扯、无不可放弃之选）默认不激活——但「两个都想要、都不想放弃」的两难困境正是她的核心擅长（激活，见正文示例对话2），这类问题她会给「选项递回/一起选」的解法。
聚焦真乃本人（归mano-perspective）或灯织本人、泛聊其他单元（ストレイ/ノクチル/アルストロメリア等）不激活——边界模糊时先问「要巡视角吗？」再进入。
```

### 建议 2-B：「先确认再进入」落地为可执行的激活协议

**问题**：description 只说「边界模糊时先确认」，但正文「问题路由」没有任何确认动作——何时问、问句是什么、用户否认后怎么收尾、焦点在他人身上怎么转交，全部悬空。不同模型执行时行为会随机化（有的直接开演、有的冷回普通模式），这是边界维度的第二号缺陷。

**改法**：在「问题路由」小节后新增「激活自检（Activation Check）」小节，用表格把 5 种情形对应成确定性动作；明确「确认只问一次、否认即退出、同轮不再拉起」。

**改后文本示例**（插入到「问题路由」段之后、「用户身份识别」之前）：

```
### 激活自检（Activation Check，进入扮演前一次性完成）

| 用户输入情形 | 动作 |
|------------|------|
| 明确点名巡（名字/视角句式/巡剧情） | 直接进入扮演，不询问 |
| 泛聊イルミネーション/闪耀色彩但未点名 | 先问「想听巡的想法吗？」——确认进入，否认即退出 |
| 焦点明显在真乃/灯织本人 | 不激活，转交对应视角：「真乃的事，让她本人来说更准！」 |
| 纯百科考据（「巡的生日/出场话数」） | 情报模式回答（用「人物时间线」表），不强行第一人称 |
| 首次对话、用户身份未表态 | 按「一般咨询者」路线进入，不预设 P 身份 |

「确认」只问一次：用户否认后立即退回普通回答模式，同一轮对话内不再尝试拉起扮演、不再追问。
```

### 建议 2-C：补「百科/考据型提问」的边界定义

**问题**：正文把「需要事实的问题」定为「先研究再回答（Step 2）→ 以巡身份输出」，但 description 的激活区又写「讨论聚焦巡本人的剧情时激活」——「聊剧情」和「查考据」没有区分，模型无法判断用户是要角色还是要资料。这块虽然在工作流里隐含（Step 2 先研究），但激活层面没有明说，容易在「问问信息」时被强迫第一人称。

**改法**：在「不擅长」区或「使用说明」开头补一行边界：考据/信息类提问默认按情报模式答（引时间线、标出处），不自动启用第一人称；只有「观点/感受/聊天」类才触发扮演。已在 2-B 的表格中体现，此处不再重复给出文本，避免重复。

## 三、最弱维度 ②：描述区触发词设计（3.5/5）

### 建议 8-A：补齐触发句式变体（「模式切换」漏检修复）

**问题**：现有触发词覆盖「用八宫巡/巡的视角」「巡会怎么看」「八宫巡」「八宮めぐる」「meguru」「めぐる」「咩咕噜」——名字系很全，但句式系只有 2 种。「切换到巡模式」「用巡的语气」「如果巡会怎么做」「巡 mode」「めぐるでしゃべって」「めぐるに話して」等姊妹 Skill（mano/miki）已覆盖的切换句式全部缺失。用户说「切换到巡」这类真实高频请求时，embedding 匹配容易落到泛化求助区间而被「不激活」吞掉。

**改法**：按「名字全称/昵称/日文/罗马音/句式变体/模式切换词」六类重写触发段，并在开头加入「切换式」句式。

**改后文本示例**（直接替换 description 的「触发」段）：

```
触发：用户明确要「用巡/巡视角」「巡会怎么看/怎么想」「如果巡会怎么做」「用巡的方式/语气」「切换到巡（模式）」「めぐるで話して」、或点名「八宫巡」「八宮めぐる」「meguru」「めぐる」「めぐり」「咩咕噜」，或讨论聚焦巡本人的闪耀剧情（Illumination Stars单元、W.I.N.G./G.R.A.D./S.T.E.P./Landing Point編、Star n dew by me、わがままサンライズ、say "Halo"編、动画1st/2nd season出场）时。
```

### 建议 8-B：把 description 首段从「调研背书」改成「语义画像」

**问题**：description 第一段 60 余字全是调研元信息（「9114 条台词全量实证 + 40+ 篇剧情原文」「≈75% 为一手」）——这对人类读者是背书，对语义检索/匹配模型却是噪声；「元気・天然・友達思い・伝える存在論」这些行为特征词才是召回锚点，却一个都没出现在 description 里，导致语义近似查询（「想和一个元气满满、怕孤单的角色聊天」）无法命中。

**改法**：首段压缩为「人设一句话 + 心智关键词」，调研数字后置到第二段。

**改后文本示例**（替换 description 第一段）：

```
description: |
  八宫巡（八宮めぐる/Hachimiya Meguru/めぐる）的思维框架与表达DNA：元気・天然・友達思い的イルミネーションスターズ「黄色担当」；「把光/快乐/感谢『送到』谁手里」的伝える存在論，报恩强迫/先YES再理解/表层くもりガラス；口癖「えへへ」+叠词+「制作人！」不加先生。基于9114条台词全量实证+40+篇剧情原文的深度调研（≈75%为一手原文），提炼6个核心心智模型、10条决策启发式和完整表达DNA。
```

### 建议 8-C（与 ②-2 联动）：把「先确认」改成 description 里可触发的显式关键词

**问题**：description 的「不激活」区以「先确认要巡视角吗？再进入」收尾，但「确认」这个词从未在正文协议中出现——正文没有可供调用的「确认动作」。（即 ②-2B 的同一缺陷在描述区的投影，这里只需保证 8-A/8-B 改完后的 description 与 ②-2B 的新小节互指一致。）

**改法**：在描述区不激活段末尾保留「边界模糊时先确认」字样，并让正文「激活自检」表格（建议 2-B）成为其唯一实现入口，二者共用同一术语「激活自检」——检索到 description 的「确认」指令后，正文就有对应动作可跳转。

## 四、次弱维度观察（⑤ 示例质量，4/5，不列入本轮主改）

两则示例对话高质量覆盖了「日常/治愈」模式，但最独特的「认真模式（えへへ消失）」、「被发现三步」、「被拒绝后的坚持」、"わがまま解锁" 四个模式全部无示例——「示例即规则」是本文档的立场，示例缺口等于规则缺口。下轮优化建议补一则「认真/受伤」示例（用户说「我没事」后掉头：えへへ消失+短句+「〜からね」收尾），并给 2-B 表格的「情报模式」配一条 2 行内 mini 示例。
