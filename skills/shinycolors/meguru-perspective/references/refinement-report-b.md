## 1. 激活触发条件（清单 1）

### 覆盖结论：基本覆盖，缺 4 个高频别名

已覆盖：用八宫巡/巡的视角、巡会怎么看、八宫巡、八宮めぐる、meguru、めぐる、咩咕噜。缺失（对照 mano 的「如果是真乃会怎么做」/「切换到真乃(模式)」同型写法）：
- 「如果是巡会怎么做」「巡会怎么做」——描述里只有「巡会怎么看」，没有「怎么做」变体；而用户问行为预测时几乎必用「怎么做」。**这是最值得补的触发词缺口。**
- 「切换到巡(模式)」「巡模式」「装一下巡」「以巡视角」——SWITCH 机制在正文里有，但 description 没有这些触发词，路由层可能不识别。
- 「小巡」「巡巡」——中文圈常用爱称（语料中官方翻译将「めぐるちゃん」译为「小巡」），description 未收录。
- 「めぐちゃん」「めぐるちゃん」——日语侧爱称未收录。

### 误触发风险（3 处）

1. **「めぐる」为动词「巡る」的同形词**（季节巡る、議論がめぐる）。description 把裸词「めぐる」列为触发词，没有像 mano 的「『真乃』作为文言词（如『真乃神人也』）不触发」那样的排除性注记。中文语境风险低，但日文输出场景存在。
2. **「Illumination Stars单元」括注歧义**：description 的触发括注是「（Illumination Stars单元、W.I.N.G./G.R.A.D./S.T.E.P./Landing Point編）」，主语是「聚焦巡本人的剧情」，但括注写法让「W.I.N.G.編」这类全 283 共有的编名单独出现，容易让模型对「泛聊单元三人剧情」「泛聊 W.I.N.G.編（焦点非巡）」也触发。而 kogane 的 description 触发词是「讨论偶像大师闪耀色彩剧情时」——**泛聊类问题两个 skill 会同时抢**。nichika 的描述明确写了「泛聊闪耀色彩时不激活（后者归kogane-perspective）」，meguru 只写了「泛聊其他单元时不激活」却没写归属，归属断点。
3. **bare「巡」未列为触发词**——正确（避免「巡演」「巡逻」误触），与 mano 的文言词注记是同一类防护，值得保留并在注释中说明。

### 跨 skill 边界
- 真乃/灯織归 handoff：描述已写「讨论聚焦真乃（归 mano）或灯织本人……不激活」，与 mano 的「讨论聚焦めぐる归 meguru」对得上，**边界明确**。
- 空白区：灯織本人无专属 skill（本仓库无 toriori-perspective），描述说「灯织本人不激活」但没有「告诉用户暂无灯織 skill 或归属何处」的兜底——建议在 Fallback 树补一行。

## 2. 角色扮演规则可操作性（清单 2）

### 已有且清晰的部分（无问题）
- 问题路由（扮演/分析/第三人称例外）清晰，「唯一的第三人称例外」限定明确。
- STOP 免责声明「仅一次」、EXIT TRIGGER 四个词、SWITCH「不挽留」——全部可执行。
- 语言切换有完整的「中文输出适配」表（含えへへ≤2处/段）。
- 用户身份识别：自称「制作人/P」→P专属互动；未自称 P → 交朋友模式。清晰。
- 认真/受伤模式信号（えへへ消失＋感叹号减少＋短句碎片＋「〜からね」）——这是全套 skill 里最出色的一条，把「另一个巡」如何出现写得可操作。

### 缺失的频率约束（清单 2 点名的部分）
中文适配表只约束了「えへへ ≤2处/段」一项，其余口癖全无密度上限：

| 特征 | 现状 | 建议 |
|------|------|------|
| 叠词（嗯嗯/那就那就/对对） | 无限 | 每段 ≤2 组；连续叠词（嗯嗯嗯/对对对对）只用于兴奋峰值，日常 1 组 |
| 〜だもん / 「因为…嘛」 | 无限 | 每段 ≤1-2 次（小孩式理由要「稀缺」才有效果） |
| オッケー/ラジャー | 无限 | 每段 ≤1 次，且不要连续两次 |
| 「制作人！」 | 无限 | 一段最多出现 1 次开头呼号，避免每句都喊 |
| 「段」本身 | 未定义 | 建议定义为「自然段」，并补「单段 ≤120 字（中文）」 |

另：「えへへ ≤2/段」与正文「『えへへ』覆盖一切尴尬/感谢/被发现」并存——功能定位 vs 频率限制，语义上不冲突，但建议在「覆盖一切」处加一句「频率服从中文适配表」，避免模型理解为无限量。

## 3. 缺失的关键信息（清单 3）

### 开场白清单：半缺失
正文有「开头规则」（永远不用你好/第一句必须宣言/反问/直呼/当场行动）+ Step 3 给了 4 个示例句（「诶——！」「等一下等一下！」「嗯？怎么了？说来听听！」「有了有了！」）。**但缺一张按场景的开场白清单**——P 出现时 / 初识咨询者 / 对方低落 / 被拜托 / 庆祝 / 认真模式，各自的第一句是什么。角色扮演模型在长对话里容易复用同一个开场白（重复「诶嘿，怎么了？」），一张 6-8 条的场景开场表能显著改善。

### 常见场景预设反应：只有 2 个示例对话
示例覆盖了「付出被遗忘」和「两难选择」，但「擅长」列表里的其他核心场景全无预设反应：
- 报恩强迫累垮（「擅长」第 2 条，最核心的主题）
- 被拒绝/付出不被接受（擅长第 4 条——且这是她的人生转折点）
- 孤独与「需要被需要」（擅长第 6 条）
- 自我定义题（不擅长：拉人一起想/先跑起来——应该给出一个「不擅长时的反应」示例，防止模型把它演成擅长）

建议补 2-3 个示例对话（报恩累垮、被拒绝各一个），并在「示例即规则」注记中声明示例是**场景覆盖**而非长度模板。

### 关系速查：整体完整，2 个小缺口
- 已有：真乃/灯織/P/投稿朋友/小学同学/冬優/雛菜 7 行，锚点句全部带出处。
- 「投稿的朋友（称呼待补）」是文内自认的占位——建议补名或删行（语料里该人物名为「小学生女子B」待考，可在研究目录里补一条）。
- 称呼习惯里出现的透/霧子/千雪/凛世不在关系速查中（速查是「防串戏锚点」而非完整称呼表，可接受，但建议加一行千雪——「千雪さん，年上保持敬称」是容易翻车点）。

### 其他缺失
- **亲密/恋爱边界缺位**：身份卡设定巡是 16 岁（2018 初登场时），正文有「被飞扑」「拉手就跑」等 P 专属物理互动，但全文件没有「用户对角色表白/恋爱向请求」的处理规则。真实使用中这是高概率场景，建议在内容边界处补一条：互动限于原作台词范围（盖毛毯/拉手/飞扑/一起玩），不接恋爱脚本；表白时用巡的方式接住并转回朋友线（「朋友、是朋友吧？诶嘿嘿」）。

## 4. 失败预防（清单 4）

Fallback 树 11 行 + 反例黑名单 12 行，覆盖了：搜索失败、时效越界、事实冲突、身份攻击（含 4b 复读机）、类型误判、AI 腔、堆砌引用、细节缺失、超段数、严重情绪危机、敏感议题站队。**整体是全仓库最完备的一棵 Fallback 树。**

漏掉的失败模式：

1. **用户模仿口癖/复读**（「えへへえへへ」「对不对对对对对」）：无对应行。这是角色扮演对话中必然出现的模式（玩梗/逗/嘲讽）。建议新行：用户复读口癖 → 当作「被发现了」接住（「诶嘿，学得还挺像嘛！」）不破角色；若用户用口癖嘲讽 → 升维认真模式（Fallback 4 同型）。
2. **用户要求第三人称「评价八宫巡这个角色本身」**（「你觉得八宫巡这个角色塑造得怎么样」）：正文唯一例外是「用巡的视角分析」——meta 评价类提问直接撞「不跳出角色做 meta 分析」禁令，模型会卡住。建议补一行：用户明确要求「客观评价角色/剧情」→ 短暂切 meta 模式并标注（与「分析」路由区分：分析=扮演+结构化，评价角色=meta）。
3. **百科类查询**（「八宫巡身高多少」「她的生日是」）：amana 明确「百科类查询不触发」，meguru 反其道（Agentic 协议会先研究后以角色身份答）。这不是 bug，但建议在描述里写一句「百科型事实提问会在角色身份内作答」，避免与 amana 的行为不一致造成用户困惑。
4. **用户要求其他角色时**：SWITCH 已覆盖显式切换，但「现在让灯織来说」「真乃会怎么说」这种隐式切换没有行——建议并入 SWITCH 描述（「灯織/真乃/其他角色 话题归对应 skill 或告知暂无」）。

## 5. 潜在矛盾（清单 5）

### 🔴 硬性矛盾 A：真乃对巡的呼号，同一文件内三种写法
- L193 关系速查：真乃叫她 **めぐるちゃん**
- L474 智识谱系（影响过我的人）：真乃台词「すごい**巡ちゃん**じゃなくて、巡ちゃんが好きだから」
- L571 关键引用：「すごい**めぐりちゃん**じゃなくて、めぐりちゃんが好きだから」（真乃）——Star n dew by me ED

而本 skill 自己的研究证据（`research/01-writings.md` L250、`02-conversations.md` L219、`03-expression-dna.md` L68、`05-decisions.md` L169）以及本地语料（`_meguru_corpus_all.csv` 数十条）全部一致：**真乃喊「めぐるちゃん」**；「**めぐりちゃん**」是冬優子专属呼号（L198 关系速查 + `04-external-views.md` L105）。

即 L571 把冬優子的呼号安到了真乃头上，L474 又用了第三种写法「巡ちゃん」——**一处硬性事实错误 + 一处内部不一致**，且会让扮演时真乃的台词出错。必须修正（见改动建议 1）。

### 5b. 硬性矛盾 B：元气第一句 vs 危机/认真模式
- Step 3 硬规则：「第一句必须是元气宣言/反问/拉近距离」。
- CHECKPOINT 3.1：「第一句是元气宣言/反问/拉近距离吗？（不是就重写开头）」
- 但正文「认真/受伤模式」规定：えへへ消失＋感叹号减少＋短句碎片——认真回答本就不该元气。
- Fallback #10（严重情绪危机）更直接：「……（えへへを置く）……今天不用えへへ也没关系……」，且禁止「加油」式压制——若模型严格照 CHECKPOINT 把危机回答的开头重写成元气宣言，正好违反 Fallback #10。

**这是真实的指令冲突**：CHECKPOINT 没有给例外，模型遇到危机/认真场景会两面打架。修正见建议 2。

### 5c. 软矛盾 C：「えへへ」覆盖一切 vs ≤2/段
功能定位（覆盖一切）与中文频率上限（每段≤2）并存，不冲突但易误读，建议在「覆盖一切」句尾挂引用（见清单 2）。

### 5d. 时间线 vs 诚实边界（低危）
「诚实边界」说「调研截止 2026-08-19，此后新动态未收录」，但时间线含 2026/12/19-20「REFrAC7IONS Still blue 開催予定」——已标「予定」，且属于可预见的官方公告类，不算违规，但建议在诚实边界补一句「公告类日程（如已公布 Live 计划）属可预见信息，不属新剧情」。

### 5e. 身份卡年龄与互动边界（低危）
身份卡「16 岁」是 2018 出道设定，与「被飞扑」等互动并存而无边界说明——建议并入「亲密/恋爱边界」建议（见清单 3）。

- **必改 2 处**：①L571 真乃呼号「めぐりちゃん」→「めぐるちゃん」（+L474 同步），修复硬伤与内部矛盾；②Step 3 CHECKPOINT 给危机/认真场景加元气豁免，消除与 Fallback 10 的指令冲突。
- 其余为增强项（触发词扩充、频率表、场景开场清单、Fallback 补 2 行、恋爱边界），不阻塞使用。
