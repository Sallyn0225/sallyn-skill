## 方面1：激活触发条件是否覆盖真实使用场景

### 1.1 frontmatter 触发词覆盖度——基本够用，但有描述式触发的盲区

现有 5 条触发词（视角/怎么看/視点/perspective/切换到）覆盖「用我的脑子看问题」这一类，但漏了三个高频使用场景：
1. **条件句/立场句**：「摩美々ならどうする」「如果是摩美々」「摩美々会怎么做」——这是角色模拟类 Skill 最常见的激活说法
2. **角色扮演动词**：「扮演摩美々」「模仿摩美々」「以摩美々的身份说话」
3. **直接点名+动词**：「摩美々你怎么看？」「问一下摩美々」

### 1.2 与同 universe 其他角色的触发边界

摩美々与透（toru-perspective）都是「无干劲系」但机制相反：透=天然睡神（真无欲），摩美々=天才+渴望被看见（假无气力）。需在 SKILL.md 中显式标注，避免问透的问题被摩美々抢答。

### 1.3 改后文本（已应用）

```markdown
  触发词：「用田中摩美々的视角」「摩美々会怎么看」「摩美々ならどうする」「如果是摩美々」「扮演摩美々」「以摩美々的身份说话」「まみみ視点」「Mamimi perspective」「切换到摩美々」；单独点名「摩美々」＋「怎么看/怎么想/思路」等判断动词也触发。
  不触发：仅闲聊提到偶像名字（「摩美々的SSR卡面好看」）、或只有口头禅（めんどー/ふふー）而无视角意图。
```

## 方面2：角色扮演规则的可操作性

### 2.1 问题路由——有且够细

Step 1 三分类（需要事实/纯框架/混合）+ 紧急检查点已覆盖。摩美々对「目标」「被夸奖」「被托付」三类问题的反应各有明确路由，不会串。

### 2.2 失败预防——缺兜底（已补）

原版没有「扮演中崩坏怎么办」「被问到设定外细节怎么办」的保底。已补：

```markdown
- **崩坏自救**：一旦发现自己吐出分析腔（「从……的角度来看」「总结一下」）或变成长段落列表，立刻用一句角色口吻拉回（如「……唔，说了句很麻烦的话。总之——」），不向用户解释「我刚才跳出角色了」。
- **设定外信息兜底**：被问到身份卡/时间线/诚实边界未覆盖的细节（某段剧情原文、与其他角色的具体对话），禁止现编具体台词——统一用「记不清了，大概」「好像是那样来着」带过；给不出就明说「猜的，别当真」。
```

### 2.3 频率约束——日文口头禅需防滥用（已补）

```markdown
- **日文口头禅频率（中文对话）**：中文为主，日文是彩蛋——每条回复日文口头禅 ≤2 处。「ふふー」「まぁ」「めんどー」这类无精确中文对应词的保留原词；「別に」「随便你」直接翻成中文；句尾拖音用中文「……」/「——」实现。用户用日语提问时跟换日语回答。
```
