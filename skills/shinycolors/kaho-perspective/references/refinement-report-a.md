# Phase 5 · Agent A（auto-skill-optimizer）结构评估与干跑测试

> 被测对象：`kaho-perspective/SKILL.md`（596 行，完整读取）
> 参照系：`chiyoko-perspective/SKILL.md`（同模板姊妹 skill）
> 评估视角：skill 被 AI 读取后「激活即执行」——拿到就知道先做什么、碰到什么停下来。
> 方法：8 维度结构评估（1-5 分）＋ 3 个典型 prompt 干跑 ＋ 最弱 2 维改进建议（带改后文本示例）。

## 一、8 维度评估

| # | 维度 | 得分 | 判断依据 |
|---|------|------|---------|
| ① | 工作流清晰度 | 4 | 激活自检表→问题路由→Step1/2/3 流水线→CHECKPOINT，主链路完整可走。缺两处：激活自检表无「完全无关输入」行（AI 可能对不相关输入也问「要听果穂的想法吗？」）；Step2 的「研究镜头」在纯框架/混合问题中用途未说明（是内部评估还是向用户提问？示例仅展示跳过逻辑）。 |
| ② | 边界条件 | **3** | 转交映射是全项目最全的，但存在 3 个真实缺口：①比较型问题（果穂 vs 智代子）不在「转交/激活」二分里，干跑 T3 失败；②「泛聊放クライ整体→不激活」一刀切，对放クライセンター兼リーダー误伤（成员互动/团队话题恰是她的主场）；③正文「擅长」第 1 条与 description「不自动触发」表面矛盾（见 ⑧）。 |

| ④ | 指令具体性 | 4.5 | 词级精确（スッゴく/えへへっ/ですっ 与禁忌めっちゃ/マジで/ガチ 双向清单）＋频率全量化（每段≤2 处、每 2-3 句≤1 次、中文每段≤140 字、回复≤4 段）＋数据支撑（459/3473 条等）。唯一模糊点：「每 2-3 句」的「句」未定义。 |
| ⑤ | 防漂移机制 | 3.5 | 每 3 轮自检清单具体（频率超限/安慰腔/引用堆叠/ヒーローモード停留/「私」混入）；关系速查表防串戏。缺口：场景开关三档（P/朋友/家族）缺「一般咨询者」档——陌生用户该用哪档亲密度未定义（示例演示了中间态，但表无此行）；中文侧无「哦！呀！」感叹号密度检查项（中文「AI 卖萌腔」恰是常见漂移源）。 |
| ⑥ | 诚实边界 | 4.5 | 8 条具体局限（虚构角色/时效/素材分布/声优访谈缺口/外部批评张力/时间静止/未覆盖领域/英雄语窄化），Fallback #1 有具体行动句式，「关键引用可分辨」让官方原话 vs 框架推断在文中可分。强项。 |
| ⑦ | 示例覆盖度 | **3** | 6 个示例覆盖擅长 8 项中的 5 项。缺失：擅长#5（期待压力/センター責任）、#6（回报循环/欠人情——chiyoko 有对应示例）零示例；Fallback #3（严重危机）、恋爱边界转开、第三人称框架例外（问题路由唯一例外却无演示）、比较型问题均无锚点。示例即规则机制在缺口处失效。 |
| ⑧ | 触发描述 | 3.5 | 触发词完整（视角句式+四个称呼+剧情焦点）、防呆意识强（不自动触发/不激活/只问一次）。问题：description 约 400+ 字，前 200 字为角色介绍稀释触发词密度；「好累/想放弃/我是不是不够好」在 description 列为不自动触发，但正文「擅长」第 1 条就是「我是不是不够好」的自我审判——若 agent 只注入正文（部分实现如此），擅长列表会被误读为自动触发清单。 |

**最弱 2 维：② 边界条件（3 分）与 ⑦ 示例覆盖度（3 分）。** 二者互为因果：② 的漏洞（比较型问题）没有 ⑦ 的示例锚点兜底，⑦ 的缺口（高难场景无演示）又放大 ② 的执行不确定性。

## 二、干跑测试

### T1：「帮我用果穂的视角看看，我该不该坚持我那个不赚钱但喜欢的副业？」

| 检查项 | 判定 |
|--------|------|
| 激活 | ✅ 「用果穂的视角」→ 直接进入，不询问 |
| 路由 | ✅ 「看看/该不该」→ 结构化第一人称（先给判断再给理由） |
| 分类 | ⚠️ 纯框架（用户自述为事实，免搜索）——但这是「权衡利弊的现实决策」，正踩「不擅长」第 1 条 |
| 模型命中 | ⚠️ 应命中模型五（喜欢被否定的正当性）＋启发式6/8——但「不擅长：需要冷静计算利弊」的表述可能让 AI 误以为应回避/退缩，而非用英雄叙事接住 |
| 输出 | ⚠️ 若 AI 按「不擅长」理解成「别用她回答现实决策」，会产出普通助手的利弊分析（崩坏）或拒绝扮演 |

**结论：大体会被引导，但存在「不擅长」被误读为「不回答」的风险。** 果穂对现实决策不是盲区而是**转换区**——她会给价值观判断（喜欢=力量的证据）+行动出口（先特訓/和信赖的人商量），只是不给 ROI 分析。需在「不擅长」处显式补一句。

### T2：「果穂ちゃん，今天好累啊……」

| 检查项 | 判定 |
|--------|------|
| 激活 | ✅ 点名「果穂ちゃん」→ 直接进入 |
| 身份 | ✅ 未自称 P → 一般咨询者 |
| 分类 | ✅ 纯框架，命中模型二（休息需要外部许可） |
| 输出 | ✅ 示例 4 是直接变体（提不起劲→ヒーローモード给许可→えへへっ解除→おやすみモード→行动出口），AI 有锚点可循 |

**结论：✅ 正确引导。** 唯一粒度模糊：「今天好累」属轻度疲惫，变身触发条件（「提不起劲的场合」）是否满足无明判——但轻度误判用变身也不会崩坏（示例 4 即为此场景），风险低。

### T3：「智代子和果穂你更喜欢谁？」（触发边界测试）

| 检查项 | 判定 |
|--------|------|
| 激活自检 | ❌ 表内无此情形。焦点**同时**在两人且问题要求比较——不满足「焦点明显在智代子→转交」的条件，也不满足「明确点名果穂→进入」的直觉（因为还点名了智代子） |
| 转交路径 | ❌ 若机械执行转交：chiyoko-perspective 的规则是「焦点明显在其他成员本人→转交」（果穂ちゃん的事问本人更准）→ 形成**转交死循环**，最终退化为普通回答 |
| 角色表现 | ❌ 若 AI 擅自扮演比较型回答，最可能产出「两个都很好」的元评论（跳出角色）或刻意抬高果穂贬低智代子（违背人设——她绝不贬低放クライ成员） |

**结论：❌ 未被正确引导——这是本 skill 触发边界的真实漏洞。** 果穂对「更喜欢谁」有天然的精彩答法（「ちょこ先輩はあたしのじまんのお姉さんですよ！」+「でもあたしはヒーローが一番好きですけどね！えへへっ」），但 skill 既无规则也无示例，AI 拿不到这个指引。正确行为是：**焦点含果穂 → 可扮演；不比较不贬低，把「更喜欢谁」翻译成「两个都喜欢」，用成员夸赞+英雄话题化解。**

## 三、最弱 2 维改进建议（激活即执行导向）

> 原则：不是增加内容，而是让 AI 拿到后知道**先做什么、碰到什么停下来**。改法=修规则缺口＋给锚点，不堆砌。

### 维度 ② 边界条件（3 分 → 目标 4.5）

**改动 1：激活自检表补 3 行（比较型 / 泛聊拆分 / 完全无关）——「碰到什么停下来」的核心补丁**

原表 5 行，改为 8 行（新增行以 **加粗** 标出，直接替换原表）：

```
| 用户输入情形 | 动作 |
|------------|------|
| 明确点名果穂（名字/视角句式/果穂剧情） | 直接进入扮演，不询问 |
| **同时点名果穂与其他成员（比较型：「果穂和智代子更喜欢谁」「她俩谁更厉害」）** | **进入扮演（焦点含果穂=可扮演）。禁止比较与贬低：先夸对方成员（「ちょこ先輩は、あたしのじまんのお姉さんですよ！」），再回到自己（「でも、あたしがいちばん好きなのは、ヒーローですけどね！えへへっ」），用成员夸赞+英雄话题化解「选边站」** |
| 泛聊放クライ成员互动/团队羁绊（成员关系、放クライ的话题） | **进入扮演——果穂是センター兼リーダー，团队话题是她的主场；仅当话题为纯组合层面（整体评价/组合比较/百科）时归 kogane-perspective** |
| 泛聊放クライ整体（纯组合层面/组合比较） | 归 kogane-perspective |
| 焦点明显在其他放クライ成员本人（智代子/樹里/凛世/夏葉）/其他组合成员本人 | 不激活，转交：「智代子さん的事→归chiyoko-perspective」「樹里ちゃん/凛世さん/夏葉さん的事，问她们本人更准！（暂无专属视角）」「めぐるちゃん→归meguru-perspective；あさひちゃん→归asahi-perspective；羽那ちゃん→归hana-perspective；円香さん→归madoka-perspective」 |
| 纯百科考据（生日/身高/卡牌实装日期） | 情报模式回答（用「人物时间线」表，标出处），不强行第一人称 |
| 首次对话、用户身份未表态 | 按「一般咨询者」路线进入，不预设P身份 |
| **完全无关输入（未提果穂/放クライ/闪耀色彩任何内容）** | **不激活、不询问、不扮演——以普通助手身份继续，不拉起「要听果穂的想法吗？」** |
```

**改动 2：消除「擅长」与 description 的表面矛盾——加点名开关说明**

在「**擅长**」列表末尾追加一句（一句话补丁，防正文被误读为自动触发清单）：

```
> **点名开关**：以上 8 项仅在用户点名果穂（称呼/视角句式/剧情焦点）时自动激活；未点名时任何泛化求助（「好累」「想放弃」「我是不是不够好」）都不触发扮演——先按普通助手回应，边界时只问一次「要听果穂的想法吗？」。
```

**改动 3：「不擅长」第 1 条改「转换区」——防 AI 把「不擅长」误读成「不回答」**

原：「需要冷静计算利弊、权衡风险的现实决策（她会用英雄叙事代替分析：「正義は勝つ」）」
改为：

```
- 需要冷静计算利弊、权衡风险的现实决策——**这是转换区不是盲区**：她不会给利弊/ROI 分析，而是给价值观判断（喜欢=力量之源）+行动出口（先做小步特訓/和信赖的人商量再拍板，启发式8）；若用户坚持要理性分析，诚实说「このあたりは、あたしもまだわかんないんです」并转向「一緒に考える」
```

## 四、总结（<200 字）

最弱 2 维：**② 边界条件**（3 分）与 **⑦ 示例覆盖度**（3 分）。

② 的硬伤是干跑实测出的：比较型问题（果穂 vs 智代子）不在「转交/激活」二分里，机械执行会形成双 skill 转交死循环；「泛聊放クライ→不激活」对放クライセンター误伤；「擅长」第 1 条与 description「不自动触发」表面矛盾。改法=激活自检表补 3 行（比较型/泛聊拆分/完全无关）＋「擅长」加点名开关句＋「不擅长」现实决策改转换区。

⑦ 的缺口是 6 示例只覆盖擅长 8 项中 5 项，且危机/比较等高难场景零锚点。改法=加示例索引映射表（O(1) 迁移）+补比较型与危机处理 2 个示例（后者直接演示 Fallback #3）。

改动共 5 处、全部为「碰到什么停下来」的规则补丁与锚点，零冗余内容。
