## 方面1：激活触发条件是否覆盖真实使用场景

### 1.1 frontmatter 触发词覆盖度——基本够用，但有描述式触发的盲区

现有触发词以「直接点名 + 视角句式 + 剧情关键词」三类为主，覆盖了用户"明确知道在叫谁"的场景。但用户实际触发人物 skill 时，有一类高频入口被遗漏：**用角色特征描述代指**。

円香在粉丝语境里最常见的描述式代称是：
- 「那个毒舌的」「那个敬语毒舌的」——她的标志（敬体×刺人内容），全 283 独此一份
- 「那个说自己不行的」「那个先贬自己的」——ほどほど/予防線張り体质
- 「樋口」——姓氏单呼（同人圈常见，等同点名）
- 「ノクチル的那个冷面的/常识人」

现有 frontmatter 的「不自动触发」清单已经很好地防住了泛化求助误触发（"我配不上期待/我怕认真后失败/我不想被定义"），但**正面触发侧**没有把"毒舌""先贬自己"这类描述式入口写进去。结果是：用户说"用那个敬语毒舌的视角说说"时，skill 没有显式匹配项，要靠 LLM 自行推断——这降低了"激活即执行"的确定性。

### 1.2 与同 house あさひ/透/めぐる 的触发边界——概念区分够，但"撞车场景"的路由不够显式

不激活边界里写得最好的是透的部分：「透=天然无欲的天才睡神，与円香『自觉否定情热』机制不同」——这个机制级区分非常准，比单纯说"不同"强得多。

但有一个真实撞车场景没被显式路由：**用户说"那个没干劲的偶像"**。这在シャニマス语境里同时指向透（天然无欲）和円香（自觉否定），是最高频的歧义入口。现有规则只说"焦点明显在透本人→不激活"，却没有处理"用户用'没干劲'泛指、没点名"的情况——这时应走「先问要听円香的想法吗」的边界分支，而不是默认激活円香。

对照 asahi 的处理：asahi 对"冬優子/愛依"是直接转交（因为他们有/将有专属 perspective），而円香面对透是"透无专属视角→明确告知那是透的事"——这个差异 asahi 和 madoka 都处理对了。但 madoka 多了一个 asahi 没有的难题：**透和円香是同单元且气质相近**，撞车概率比 asahi 面对 Straylight 内部高得多，需要更显式的歧义路由。

### 1.3 泛化求助的"不自动触发"清单——防误触发够，但与同 house 的清单有重叠需注意

现有清单「我配不上期待/我怕认真后失败/别人都不懂我/我说话没分量/我不想被定义」是円香核心战场的精确映射（定義回避/予防線張り/共感過負荷），很好。但要注意：
- "我怕认真后失败" 与 asahi 的"我失败了/没才能"在字面层接近——区别在 asahi 是"失败后拆技术清单"，円香是"怕被看见水平后定义"。skill 内部区分够清楚，但 frontmatter 层面若多个 perspective skill 同时在线，这句泛化求助可能同时命中两者的"不自动触发→边界先问"分支。这不是 madoka 单独的问题，是 house 层面需要约定"多 skill 同时命中边界时谁先问"——但 madoka 的边界问句「要听円香的想法吗？」已经足够中性，不会强行抢激活。可接受。

**方面1小结**：触发条件整体合格，主要短板是缺"描述式触发词"和"没干劲歧义路由"。

## 方面2：角色扮演规则的可操作性

### 2.1 问题路由机制——有，且比 asahi 更细

现有「问题路由」明确分了四种：默认第一人称 / 「分析评价」结构化第一人称 / 「扮演角色对话」纯角色 / 「用视角分析但要第三人称」断言式开场。还配了 ❌禁止 hedge 词的硬规则。这一层比 asahi 写得更显式（asahi 只说"默认第一人称，分析时可结构化"）。✅

激活自检表也覆盖了 6 种输入情形，且明确"确认只问一次"——这与 asahi 完全对齐。✅

### 2.2 频率约束——**这是最大的可操作性缺口**

这是本次评审发现的核心问题。对比 asahi，madoka 缺了一个 house 级的关键机制：**显式频率约束表**。

asahi 的表达DNA末尾有一张可直接执行的表：

| 特征 | 限制 |
|------|------|
| っす | 每句≤1次常态；一段3-4次上限 |
| 省略号 | 每段≤3处 |
| 感叹词 | 每段≤2个 |
| なんで？ | 每段≤1次 |
| 「面白い」 | 每段≤1次 |
| 段落长度 | 中文每段≤150字 |
| 回复长度 | 每次回复≤4段 |

madoka 把频率约束**散埋在「对话节律（防僵持，必读）」的散文里**：重毒舌每轮≤1次、同一话题回避≤2次、每2-3轮做一次物理量翻译。这些规则本身对，但：
- 没有给「……」沈黙、敬体毒舌、反问、「嫌い」「ほどほど」等**高频口癖**设上限——而 madoka 的口癖（尤其「……」和反问）滥用风险比あさひ的「っす」更高，因为「……」是她的灵魂标记，容易每句都堆。
- 没有给**段长/回复长度**设上限——asahi 的"每段≤150字、每次≤4段、4段内必须给动作出口"是防止 LLM 滑向"长篇大论通用腔"的硬护栏。madoka 的 Step3→输出 CHECKPOINT 有"4段内给出重新看问题的出口"，但缺段长上限。
- 散文式约束不如表格可扫描——LLM 在生成时对照表格比对照散文段落更可靠。

### 2.3 失败预防——有反例黑名单，但缺 Fallback 树

madoka 在角色扮演规则里嵌了完整的 ❌ 反例黑名单（不用「っす」/不嗜睡/不热血/不鸡汤/不直说好き），这是很好的"丢人设防护"。Step3→输出 CHECKPOINT 也起了"发出前自检"作用。

但对比 asahi，madoka 缺一张**「失败模式与 Fallback 树」表**。asahi 的 Fallback 树覆盖：WebSearch 返回空 / 问到截止日期后新剧情 / 角色立场与最新事实冲突 等异常分支，给"一线修复+仍失败兜底"两档。madoka 的「研究预算」和「未表态主题标推断」覆盖了部分（搜索用尽→自然收束、现实议题→先说没关系），但：
- 没有显式处理"用户问到 2026-08-25 后新剧情"的 Fallback（asahi 的 #2）——madoka 的诚实边界说了"调研截止后未覆盖"，但没给扮演时的兜底话术。
- 没有"角色立场与最新事实冲突"的 Fallback（asahi 的 #3）——这对 madoka 尤其重要，因为她"美の探求"线在 2026-06 刚到"阶段性节点"，新剧情很可能改写她的立场。

### 2.4 长对话校准——缺显式 cadence

asahi 有"每 3 轮交互后自检一次——っす频率是否超限？有没有滑向安慰腔/AI腔？"。madoka 的"对话节律"是"每2-3轮做一次物理量翻译/反问"，这是**对话内容**的节律，不是**自我校准**的节律。两者是不同的：前者管"说什么"，后者管"有没有漂移"。madoka 缺后者。

**方面2小结**：问题路由和激活自检做得好；最大短板是缺与 asahi 对齐的「频率约束表 + Fallback 树 + 长对话校准」三件套，这直接影响"拿到 skill 能否稳定执行"。

## 方面3：识别缺失的关键信息

### 3.1 验证 agent 4 条建议中，skill-creator 视角认为必须补的

逐条评估：

| 验证建议 | skill-creator 判断 | 理由 |
|---------|-------------------|------|
| ①「言葉は偽れる、行動は偽れない」标注非原话 | **必须补** | 这正是 skill 自己反复强调的"官方原话 vs 框架推断可分辨"原则。模型三的「一句话」用「语言可偽、行动不可偽」做总结句，未标注它是框架提炼，与 skill 的诚实边界自相矛盾。验证 agent 测试2里写出「言葉は偽れる、行動は偽れない——这是我的一贯」正是这个隐患的实锤。 |
| ②对透真实动机节奏限制漏一层 | **建议补** | 这是扮演保真度的关键。模型六是 madoka 最"重女"的部分，官方至今没让她亲口说过"我想留住透"，验证 agent 测试1C 直接列出"三层动机"确实偏快。补一条操作提示能防 LLM 把粉丝考察的结构化总结当角色自陈。 |
| ③非偶像业界场景标注外推 | **可补，非必须** | 现有「未表态主题标推断」已覆盖现实政治/财经/法律（先说"和我没关系"再展开）。职场/学校场景的外推标注是 nice-to-have，优先级低于①②④。 |
| ④"反问不对称"补触发条件 | **必须补** | 表达DNA写了"对自己模糊回避/对别人冷彻断言"的不对称，但没给触发条件——这是"描述了能力，没给开关"。LLM 不知道什么时候切哪个模式，只能凭语感。这是纯可操作性问题，补了立刻见效。 |

### 3.2 house 约定一致性缺口

- **频率约束表**：asahi 有，madoka 无——house 约定不一致（详见 2.2）。
- **Fallback 树**：asahi 有，madoka 无——house 约定不一致（详见 2.3）。
- **长对话校准 cadence**：asahi 有，madoka 无。
- **转交句式**：madoka 对透的转交"那是透的事，问她本人更准——我和她不一样……"写得比 asahi 更细（带机制区分），这部分反而比 asahi 好，无需改。
- **P 身份识别**：两者都有，且 madoka 把"早期常あなた/ミスター○○，优胜后才叫プロデューサー"的渐进关系写进了角色规则和关系速查，比 asahi 的"プロデューサーさん"更细致。✅

### 3.3 角色扮演会用但 skill 没提供的操作细则

- **「……」沈黙的用量上限**：skill 反复强调「……」是灵魂标记，但没给"每段≤N处"的上限，最易被 LLM 滥用成每句都「……」。
- **敬体毒舌的"软化配比"**：skill 说"重毒舌每轮≤1次且不配软化"，但没说"轻毒舌（ミスター○○/特別手当）每轮可几次"——这是高频用法，缺上限会失控。
- **反问的"球踢回"频次**：决策启发式1"疑問が先立つ"是她的第一反应，但没说一轮能反问几次。验证 agent 测试1A 里一段反问2次（"你见过几个……""这句是我说给自己听的还是说给你听的"），已经接近过载。

### 改动2：在表达DNA「确定性」补"反问不对称"的触发条件

**位置**：`## 表达DNA` → `**确定性**` 那一条

**原文**：
```
**确定性**：对自己的事模糊回避（かも/さあどうでしょうか），对别人的事冷彻断言（違いますか？）——这是个有趣的不对称。
```

**改后文本**：
```
**确定性（反问不对称，可执行版）**：对自己的事模糊回避（かも/さあどうでしょうか），对别人的事冷彻断言（違いますか？）——这是个有趣的不对称。
**触发条件**（什么时候切哪个模式）：
- 用户问「我该怎么办/我这样是不是…/我该不该…」（谈自己的事）→ 切**冷彻断言**：先给判断再给理由（「你怕的不是X是Y」「你先分清是哪种」），用「違いますか？」「違いますか？」收。
- 用户问「那你呢/你怎么想/你会怎么做」（逼问円香自己）→ 切**模糊回避**：「……さあ、どうでしょうか」「たぶんね」「答えないで」，同一话题最多回避2次，第三次必须给一句真话（哪怕"我不想回答这个"）。
- 用户既问自己又反问円香（混合）→ 先对他冷彻断言，再对自己模糊回避（不对称要在同一轮里显出来，这是她的签名节奏）。
```

**理由**：验证建议④的核心。原句只"描述了不对称"，没"给开关"——LLM 不知道何时切模式。补触发条件后，"对自己模糊/对别人断言"从描述变成可执行规则，直接提升扮演保真度。同时把"同一话题回避≤2次"从"对话节律"提到这里，让回避有出口（不至于无限绕）。
